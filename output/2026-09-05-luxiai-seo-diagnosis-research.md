- 성능(Core Web Vitals)은 Google 검색 순위에 직접 반영되는 요소이므로, SEO 92점이라는 숫자만으로는 검색 경쟁력을 낙관할 수 없는 상태입니다.

## 2. 개선 과제 TOP 5

### 1순위 — 이미지 용량 최적화
- 예상 절감 용량: **5,767KiB** (전체 페이로드 15,274KiB 중 약 38%)
- 차세대 이미지 포맷(WebP/AVIF) 적용, 반응형 이미지 크기 제공으로 LCP(19.6초) 개선에 가장 직접적인 효과

### 2순위 — 레이아웃 안정성 확보 (CLS 개선)
- 현재 CLS 0.676 (기준치 0.1 대비 매우 불안정)
- 원인: 이미지 요소에 width/height 미지정, 합성되지 않은 애니메이션 요소 7개
- 이미지 크기 속성 명시 + 애니메이션을 transform/opacity 기반으로 전환 필요

### 3순위 — 사용하지 않는 자바스크립트 제거 및 실행시간 단축
- 사용하지 않는 JS: 2,136KiB, JS 실행시간 3.6초, 총 차단 시간(TBT) 760ms, 긴 작업 20개
- 코드 스플리팅, 불필요한 서드파티 스크립트 정리로 상호작용 반응성 개선

### 4순위 — 캐시 정책 설정
- 예상 절감 용량: 2,313KiB
- 정적 리소스(이미지·JS·CSS)에 장기 캐시 헤더 적용 → 재방문 속도 개선

### 5순위 — 이미지 대체 텍스트(alt) 및 링크 접근성 보완
- 이미지 alt 속성 누락이 SEO·접근성 항목에 공통으로 지적됨 (크롤러의 콘텐츠 이해도에 직접 영향)
- 인식 불가능한 이름의 링크도 다수 발견 → 스크린 리더·크롤러 모두에 불리

## 3. 참고 — 우선순위 밖 이슈
- 보안 헤더 미흡: CSP, HSTS, COOP, XFO, Trusted Types 모두 미적용 (권장사항 점수 50점의 주요 원인)
- 색상 대비 부족, 터치 영역 크기 부족 (접근성)
- 서드파티 쿠키 사용, 콘솔 오류 발생

## 4. 활용 메모
- 픽온 입장에서는 "이미지 최적화·페이지 속도"를 경쟁사 대비 차별점으로 콘텐츠화할 수 있는 근거 자료로 활용 가능.
- 발행용 콘텐츠(블로그·SNS 등)로 전환 시, 경쟁사를 직접 깎아내리는 표현은 피하고 "우리가 왜 빠른 페이지를 신경 쓰는지"에 초점을 맞출 것.
